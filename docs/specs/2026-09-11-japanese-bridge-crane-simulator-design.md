# 日式渡橋機訓練模擬器設計規格

日期：2026-09-11  
狀態：待使用者最終審閱  
參數基準：`Japanese_Bridge_Crane_Physics_Parameter_Baseline_v0.1.md`

## 1. 目標

建立一款可在 iPhone Safari 橫向全螢幕遊玩的 3D 日式渡橋機訓練模擬器。歷史 `v0.1` 基準描述「上重下輕盒裝 Figure＋兩條平行圓桿＋雙爪」估算場景；可玩里程碑另用四條可獨立設定的橋桿，不改寫 `v0.1` 的來源或含義。

成功標準不是畫面看起來像，而是同一套物理參數能自然產生：

- 落位太前時失敗；
- 較後接觸時由力矩造成翻側；
- 盒逐爪滑動、旋轉、卡住或跌落；
- 不同結果均由重力、質量分布、摩擦、碰撞及有限爪力決定。

模擬器定位為訓練工具，不包含收費、登入、排行榜、多人連線或真實獎品兌換。

## 2. 已確認的產品決定

| 項目 | 決定 |
|---|---|
| 主要平台 | iPhone Safari，橫向全螢幕；桌面瀏覽器為次要支援 |
| 核心技術 | TypeScript、Babylon.js、Havok Physics、Vite |
| 操作方式 | 日式兩段式：預設第一掣令機頭向右移，第二掣令機頭向遠離玩家方向移；每次放手即鎖定該軸，第二掣放手後自動落爪、閉爪、升爪及復位。軸方向可由機台 profile 鏡像，但一局途中不可改變 |
| 模式 | 實機視角練習＋可開關的分析模式＋慢鏡重播 |
| 獎品 | 第一版只有一款原創盒裝 Figure；可調尺寸、質量及三維重心 |
| 場景 | 日本紅白連鎖機舖氣氛；原創品牌、角色、招牌及包裝 |
| 品牌邊界 | 可呈現 Taito Station 類型氣氛，但不得使用 Taito Logo、官方字樣或複製受版權保護的 Figure 包裝 |
| 部署 | 純靜態網站，開網址即可玩；無後端依賴 |

## 3. 交付範圍

### 第一版包含

1. 一部完整可操作的雙爪渡橋機。
2. 一個上重下輕的盒裝 Figure 剛體模型。
3. 可調橋桿直徑、中心距、高度差及表面摩擦。
4. 可調盒尺寸、質量、三維重心、恢復係數及阻尼。
5. 可調爪臂幾何、閉合力、關節阻尼及運動速度。
6. 正面及側面觀察鏡頭；正常操作時限制自由視角。
7. 重心、接觸點、合力、支撐區及速度向量分析圖層。
8. 每一爪的初始狀態、輸入、參數及軌跡記錄。
9. 慢鏡重播、前一爪還原及 A/B 落點比較。
10. 物理驗證測試頁及參數來源／可信度顯示。

### 第一版不包含

- 軟身公仔、枕頭、布料或繩索模擬；
- 多款機台、多款爪頭或隨機獎品；
- 帳戶、雲端存檔、社交分享、排行榜、付款或廣告；
- VR／AR；
- Taito、Bandai Namco、Banpresto 或其他第三方商標與素材；
- 聲稱精確複製任何指定營運門店的秘密設定。

## 4. 系統架構

### 4.1 模組

| 模組 | 責任 | 主要依賴 |
|---|---|---|
| `AppShell` | 啟動、路由、載入狀態、裝置能力檢查 | Browser APIs |
| `RenderWorld` | 場景、燈光、材質、鏡頭及視覺插值 | Babylon.js |
| `PhysicsWorld` | 固定步長、Havok world、碰撞群組及診斷 | Havok Physics |
| `PrizeBody` | 盒碰撞體、內部質量塊、重心及慣量 | `PhysicsWorld` |
| `BridgeRig` | 兩桿幾何、位置、高度差、接觸材質 | `PhysicsWorld` |
| `ClawRig` | 機頭、懸吊、雙爪、有限力矩關節 | `PhysicsWorld` |
| `CraneSequence` | 兩段式移動及落爪狀態機 | `ClawRig`, `InputController` |
| `InputController` | 觸控、滑出、轉屏及頁面失焦處理 | Pointer Events, Page Visibility |
| `CalibrationProfile` | 參數值、單位、範圍、來源、可信度及版本 | JSON schema |
| `ReplayRecorder` | 初始快照、輸入事件、物理採樣、重播及比較 | `PhysicsWorld` |
| `AnalysisOverlay` | 重心、力、接觸、支撐區、落點及圖表 | Babylon.js GUI / HTML overlay |
| `AudioScene` | 馬達、閉爪、撞擊及機舖環境聲 | Web Audio API |
| `PerformanceManager` | 量度 FPS／記憶體壓力並調低非物理畫質 | Browser capabilities |

每個模組須由明確介面溝通；物理層不得依賴 UI 或畫面幀率，視覺層不得直接改寫剛體位置。

### 4.2 資料流

1. `CalibrationProfile` 建立機台、盒及接觸參數。
2. `CraneSequence` 接收經 `InputController` 正規化的按住／放開事件。
3. 機頭使用受速度及加速度限制的運動目標移動。
4. 爪使用有限力矩關節追蹤目標角度，物理接觸可阻止其到達目標。
5. `PhysicsWorld` 以固定步長運算；`RenderWorld` 只插值顯示結果。
6. `ReplayRecorder` 記錄每一步的輸入、關鍵剛體狀態及接觸摘要。
7. `AnalysisOverlay` 讀取只讀診斷資料，不施加任何力。

## 5. 操作狀態機

狀態固定為：

`BOOT → READY → MOVE_AXIS_1 → MOVE_AXIS_2 → DROP → CLOSE → LIFT → RETURN → SETTLE → REVIEW`

規則：

- 第一掣按住時，機頭預設只向右移動；放手即鎖定左右軸位置。
- 第二掣按住時，機頭預設只向遠離玩家方向移動；放手即鎖定前後軸位置，之後不可再修正。
- 不同機台 profile 可以在開始一局前鏡像任一軸方向，但必須在 HUD 清楚顯示，而且一局途中不可改變。
- `DROP`、`CLOSE`、`LIFT`、`RETURN` 由狀態機自動完成。
- 頁面失焦、手指滑出控制範圍、來電／切 App 或轉屏時，當前手動移動立即停止；系統不會把失焦誤當成第二掣放手並自動落爪。
- 自動流程開始後，重新獲得焦點只恢復顯示，不重播或跳過物理步。
- 一局無限練習次數；使用者可以回復到前一爪初始快照。

## 6. 物理模型

### 6.1 時間與穩定性

- 標準重力：`9.80665 m/s²`。
- 物理更新：固定 120 Hz；畫面目標 60 FPS，最低可接受 30 FPS。
- 畫面變慢時不改變物理時間步長或摩擦／爪力。
- 爪尖、盒及圓桿啟用連續碰撞偵測或等效的 swept collision。
- 接觸容許穿透不得超過參數基準規定值。

### 6.2 獎品盒

- 使用有小圓角的外部盒碰撞體。
- 內部使用 2–4 個質量塊描述 Figure、底座及包材。
- 合成重心與慣量張量由同一質量分布計算。
- 重心固定於盒本體座標；盒旋轉時重心一同旋轉。
- 不使用「傾斜角超過門檻即跌落」規則。

### 6.3 橋桿與摩擦

- 圓桿使用真正圓柱碰撞體，不使用平面或隱藏斜坡。
- 每個接觸點獨立計算法向力及切向摩擦。
- 靜摩擦滿足 `|Fₜ| ≤ μsN`；超過極限後轉為動摩擦。
- 翻倒由重心垂直投影離開有效接觸支撐區，以及當下摩擦無法維持平衡而自然產生。

### 6.4 爪臂

- 爪臂以關節連接機頭，使用角度目標＋最大力矩／力限制。
- 爪撞盒或圓桿時可以停、未完全閉合、滑脫或令懸吊偏擺。
- 不准使用 kinematic 動畫直接穿過物件。
- 閉合力為可調校曲線，可隨開口角改變；預設值必須附來源與可信度。

### 6.5 禁止的非物理捷徑

- 隱藏成功率、保夾或 payout 控制；
- 對盒施加沒有來源的吸力、推力或旋轉力；
- 接近預定落點便播放成功動畫；
- 為配合影片而在特定影格改寫位置／角度；
- 用高線性阻尼掩蓋錯誤摩擦或接觸抖動。

## 7. 參數及來源管理

每個可校準參數使用以下資料結構：

```ts
type SourcedParameter = {
  key: string;
  value: number;
  unit: string;
  allowedRange: [number, number];
  sourceKind: "measured" | "manufacturer" | "published" | "inferred" | "engineering-initial" | "unknown";
  sourceRef: string;
  confidence: "high" | "medium" | "low" | "unknown";
  calibrationDate?: string;
};
```

所有回放均保存完整 profile 版本。修改參數後，舊回放仍引用舊版本，避免分析結果被新設定污染。

## 8. 訓練介面

### 8.1 正常模式

- iPhone 橫向畫面中央顯示機台玻璃內部。
- 左下及右下各一粒大型實機式按鈕，支援按住操作。
- 顯示目前階段、剩餘可操作軸及重設按鈕。
- 正面／側面鏡頭只可在手動移動前切換；落爪後鎖定，以保持實機判位難度。

### 8.2 分析模式

- 可開關重心、重力方向、接觸點、法向力、摩擦力、速度、角速度及支撐區。
- 顯示落爪點相對盒的三軸座標。
- 提供 `0.25×`、`0.5×`、`1×` 重播速度；慢鏡只影響播放，不重新計算物理。
- A/B 比較只允許改落爪輸入；其他參數預設鎖定，確保比較公平。
- 顯示「影片推算／工程初值／已量度」標籤，低可信度不以確定語氣呈現。

## 9. 視覺與聲音

- 原創品牌暫名 `BRIDGE LAB`。
- 紅白機身、透明玻璃、金屬導軌、白光燈箱及日式機舖背景。
- 場景使用 PBR 材質，但背景機台採低多邊形及烘焙光照。
- 盒面使用原創排球／運動 Figure 設計，不重製影片中的動漫人物或包裝。
- 音效包含軸馬達、升降、solenoid 閉合、紙盒撞桿、跌落及低音量環境聲。
- 音效只由實際狀態／碰撞觸發，不影響物理結果。

## 10. 效能與兼容策略

- 首次可玩資源目標：壓縮後不超過 20 MB。
- iPhone 主要目標：60 FPS；複雜接觸時最低 30 FPS。
- 物理精度不得因畫質模式下降；效能不足時依次降低陰影、反射、背景人物、背景機台細節及粒子效果。
- 3D 資產使用 glTF／GLB、Meshopt 或 Draco 壓縮及 KTX2 紋理。
- 不以裝置型號硬編碼畫質；使用啟動測試及運行時平均幀時間選擇級別。

## 11. 錯誤與中斷處理

| 情況 | 行為 |
|---|---|
| WebGL／WASM／Havok 載入失敗 | 顯示可理解錯誤及重新載入；不可退回假物理模式 |
| 裝置記憶體不足 | 移除背景資產並保留核心機台；仍失敗則安全停止 |
| 物理出現 NaN／極端速度 | 暫停、保存診斷快照、標示該次結果無效並允許回復 |
| 轉為直向 | 暫停手動輸入並提示轉回橫向；不重設獎品狀態 |
| App 切換／頁面失焦 | 停止手動移動；回來後由暫停狀態確認繼續 |
| 音效被 Safari 阻擋 | 遊戲仍可操作，首次觸控後再啟用聲音 |
| 回放 profile 不相容 | 保留原始資料並提示版本不支援，不以新參數重算冒充原結果 |

## 12. 測試與驗收

### 12.1 數學及單元測試

- 重心合成、慣量平移／旋轉及單位轉換；
- 靜摩擦臨界條件、力矩與翻倒支撐判定；
- 狀態機合法轉換及失焦／觸控取消行為；
- profile schema、範圍檢查及版本鎖定；
- 回放事件時間排序及快照還原。

### 12.2 物理整合測試

完整採用參數基準的 10 項驗證矩陣，包括自由落體、靜止支撐、摩擦臨界角、純力矩翻倒、爪受阻、桿上滑動、FPS 不變性，以及影片 V2／V3／保留片驗證。

### 12.3 裝置測試

- 實體 iPhone Safari 橫向操作；
- 觸控按住、滑出、第二指、轉屏、切 App 及重新回到頁面；
- 30／60 FPS 條件下同一輸入的成敗一致性；
- 載入時間、記憶體壓力、機身發熱及 10 分鐘連續操作。

### 12.4 第一版完成條件

第一版只有在以下全部成立時才可標示完成：

1. 所有數學／狀態機單元測試通過。
2. 參數基準的 10 項物理驗證全部通過。
3. 同一參數集只改落爪位置，可重現影片「太前失敗」及「較後翻成出貨 Pose」。
4. 至少一段未用作調參的影片能正確預測主要轉動方向及成敗。
5. iPhone Safari 上沒有穿模、無故彈飛、持續抖動或失焦後自行落爪。
6. 所有低可信度值在介面及文件中仍標示為估算。

## 13. 實作次序

1. 建立純物理驗證場景及自動測試。
2. 實作盒、橋桿、爪臂與有限力矩關節。

4. 實作參數 profile、診斷資料及回放。
5. 校準 V2／V3 影片場景並做保留片驗證。

7. 加入原創機台、紅白機舖背景、音效及效能降級。

## 15. 可玩里程碑修訂（2026-09-12）

- 主要目標維持 iPhone Safari 橫向模式；物理固定 `1/120 s` 及 `9.80665 m/s²`，畫面效能不改物理步長或參數。
- 新 profile 固定四條獨立橋桿，保留 2–4 個內部質量塊及共同重心／慣量推導。所有可接觸實體結構須有碰撞體。
- 爪以有限致動器力矩運作；不得加入隱藏支撐、磁力、強制姿勢、腳本獎品位移或機率成功。
- 第二掣刻意放手才開始自動流程。流程加入 `OPEN → SETTLE → REVIEW`；Continue 保留獎品，只有 New setup 重設獎品。
- 中斷會凍結模擬並清除輸入；Resume 明確重設牆鐘累積且須重新按掣。取消輸入不等同放手。
- 此里程碑包括正面／側面鏡頭及可收合診斷面板。完整回放、A/B、慢鏡、聲效及最終美術留待後續里程碑。
- 完成標籤分為 engineering fixture、playable prototype、validated release；只有 validated release 滿足最終驗收。

### 不確定性紀錄

原始錄影片段目前未取得，未檢查檔案 bytes 或 SHA-256，亦沒有可支持時間、影格、端點、遮擋、接觸或尺寸的標註。四桿 profile 因此只屬低可信度工程 fixture。歷史 `0.45 m` 桿長只作工程估算，敏感度範圍為 `0.30–0.60 m`，不得稱為量度值。各桿中心、方向、截面、材質及接觸係數同樣是工程選擇；詳見 `docs/research/four-rod-annotations.md`。

橋桿本地座標定義為 Z 軸沿桿長、X 軸為截面闊度、Y 軸為截面高度。方向以右手系 intrinsic XYZ 歐拉角（degree）套用至世界 X 向右、Y 向上、Z 向深處的座標。工程 fixture 的桿 1／2 沿世界 Z，中心為 `x = ±0.08, y = 0, z = 0`；桿 3／4 沿世界 X，中心為 `x = 0, y = -0.04, z = ±0.27`，Y 軸旋轉 `90 deg`。此幾何完全是為工程測試而虛構，並非實機資料。
